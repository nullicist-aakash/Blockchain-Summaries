2.2 Get Initial Blockchain Data

Bitcoin transactions are hard to find online in raw format. Before getting hands on the raw data, we need to see how bitcoin stores all the data. Bitcoin blocks are stored in blk*.dat files. To be more specific, you will see that initial blocks are stored in:

blk00000.dat
blk00001.dat
blk00002.dat
...

Each of above files are around \(128\) mb. This value is set in MAX_BLOCKFILE_SIZE variable in Bitcoin source code.

As of today, if you download whole data, it will take around \(470\) gb and it is increasing every \(10\) minutes. We will cover the growth aspects in next volume, the rate at which new data is added to Bitcoin network.

We don’t need this much data! We don’t have RAM to load whole data and process it. We will work with first file: blk00000.dat and with only initial \(1000\) bytes in the beginning. Why? Because we will manually examine each bytes of the file and to understand how the data is structured, few examples are enough. We can always change our code to read more data, the working code remains same.

So, how to get hands on first block without downloding whole Bitcoin data? Easy! Just download the bitcoin client from official website. After that, it will ask you to download all blocks. You can start this process. Based on your OS, you need to go to directory where data is being downloaded. This must be visible on the Bitcoin Client startup when it asks you to download data. When you see the file blk00001.dat in the folder (after the download starts), you need to close the Bitcoin Core application so that it doesn’t download any more data. Simply copy the blk00000.dat file to your project. You have access to initial \(128\) mb of transactions!!

But this file still have a lot of transactions. We need to limit the size we will read, so that our dataset is limited to initial 3-4 transactions. For this, we will use the linux command:

dd if=blk00000.dat of=1k.dat bs=1000 count=1

You will see output something like this:

1+0 records in
1+0 records out
1000 bytes transferred in 0.000251 secs (3984064 bytes/sec)

What this does is take the input file blk00000.dat, split it into chunk of size \(1000\) bytes (parameter bs) and do this only once (parameter count). The output file is stored in 1k.dat. Thus, we got an access to initial 1k bytes of transactions of Blockchain! This is getting very exciting and we will read this into code very soon.

2.4 Hex Viewer

First, we will create a simple hex viewer which will let us view the byte contents in hexadecimal format. This is similar to xxd command in linux.

2.4.1 C++ Code

We will take str as input for our starting address and len specifies how many bytes we want to display starting from address str. Here is the code for our hex viewer:

#define HEX( x, len ) std::setw(2 * len) << std::setfill('0') << std::hex << std::uppercase << (((1ll << (8 * len)) - 1) & (unsigned int)( x )) << std::dec

void hex_view(const char* str, const size_t len)
{
    for (int i = 0; i < ((int)len >> 4) + (len % 16 ? 1 : 0); ++i)
    {
        int start = i * 16;
        int end = std::min(i * 16 + 15, (int)len - 1);
        std::cout << "0x" << HEX(start, 4) << " |  ";
        for (int j = start; j <= end; ++j)
            std::cout << HEX(str[j], 1) << (j % 8 == 7 ? "  " : " ");

        for (int j = end; j < i * 16 + 15; ++j)
            std::cout << (j % 8 == 7 ? "    " : "   ");
        std::cout << "| ";
        for (int j = start; j <= end; ++j)
            std::cout << (std::isprint(str[j]) ? str[j] : '.');
        std::cout << '\n';
    }
}

2.4.2 Working of hex_view

You can safely skip this portion as we will be using above code as black-box from now on and the internal working of it is irrelevant to our discussion.

Outer for loop takes care of how many lines to print. Inside the loop, we first initialise the start and end memory indices so that we don’t print out-of-bound memory by mistake. Then, we print the offsets. After that, we use HEX macro defined above to print the memory characters in specified number of bytes. At the last, we print the characters in ASCII format. Here is the summary of functions used in above code:

  1. std::setw: Present in <iomanip> header, specifies the width of output. Don’t worry if you don’t know about this. We will not use this again.
  2. std::setfill: This is used to print the given character ('0' here) instead of spaces which were introduced by setw.
  3. std::hex: This specifies that we want to print the integers in hexadecimal format. The default behaviors is std::dec which is used in last of this macro to reset the output manipulator.
  4. std::uppercase: This specifies that we want to print everything in uppercase. This ensures that we will print integer \(10\) as \(0A\) instead of \(0a\).
  5. std::isprint: This will return true if the output character is a printable ASCII character. We simply print a dot . if this is not the case, otherwise the equivalent ASCII character.

We will be using HEX again and again to display our output, so it is necessary to get familiar with the syntax.

2.4.3 Display transaction bytes

We will use the above hex_view function to see the contents of initial bitcoin data. First, we will read from .dat file using fstream. Then we will read the whole data inside character array and then, display the contents in hexadecimal format.

Here is the code to display the initial bitcoin data in hexadecimal:

#include <iostream>
#include <fstream>
#include <algorithm>
#include <string>
#define HEX( x, len ) std::setw(2 * len) << std::setfill('0') << std::hex << std::uppercase << (((1ll << (8 * len)) - 1) & (unsigned int)( x )) << std::dec

void hex_view(const char* str, const size_t len)
{
    for (int i = 0; i < ((int)len >> 4) + (len % 16 ? 1 : 0); ++i)
    {
        int start = i * 16;
        int end = std::min(i * 16 + 15, (int)len - 1);
        std::cout << "0x" << HEX(start, 4) << " |  ";
        for (int j = start; j <= end; ++j)
            std::cout << HEX(str[j], 1) << (j % 8 == 7 ? "  " : " ");

        for (int j = end; j < i * 16 + 15; ++j)
            std::cout << (j % 8 == 7 ? "    " : "   ");
        std::cout << "| ";
        for (int j = start; j <= end; ++j)
            std::cout << (std::isprint(str[j]) ? str[j] : '.');
        std::cout << '\n';
    }
}

// Returns the file contents as C++ string
std::string get_file_contents(const char *filename)
{
    std::ifstream in(filename, std::ios::in | std::ios::binary);
    if (!in)
    {
        std::cerr << "Error in opening file" << std::endl;
        throw errno;
    }

    std::string contents;

    // Allocate required memory in heap for string
    in.seekg(0, std::ios::end);
    contents.resize(in.tellg());

    // Copy contents from file to string
    in.seekg(0, std::ios::beg);
    in.read(&contents[0], (int)contents.size());

    // return the string
    return contents;
}

int main(int argc, char** argv)
{
    if (argc != 2)
    {
        std::cerr << "Usage: ./reader.out <block_data>" << std::endl;
        exit(-1);
    }

    auto contents = get_file_contents(argv[1]);
    hex_view(contents.c_str(), contents.size());
}

Understanding above code is very simple. We are taking the path of our transaction data file as command line argument. In the function get_file_contents, we pass the file path from the terminal. If we are unable to open file in binary mode for reading, we simply exit. Otherwise, we copy the contents from whole file to string and then return it. Finally, we are printing the contents of file in hexadecimal format.

Compile the above code using the following command:

g++ main.cpp -o reader.out -std=c++17

A file reader.out will be created which is our executable. Run the file using the following command:

./reader.out data/1k.dat
